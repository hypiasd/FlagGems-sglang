# Triton / Triton-TLE 指南吸收与 Task112 行动清单

来源：[赛事指南：安装 Triton 或 FlagTree、了解 Triton-TLE](https://jwolpxeehx.feishu.cn/wiki/X6CXwJqUoiJURHkw6KIc0y7InTf)。2026-10-01 通过用户已登录的 Arc 阅读；本机文本副本位于忽略目录，不提交登录信息。以下区分指南事实、本项目决策与待核验项。

## 1. 指南明确的信息

- 允许普通 Triton 或 Triton-TLE；使用 TLE 不是强制要求。
- 指南列出的 FlagTree 安装命令如下。这是推荐安装版本，不是已读取到的赛事运行时版本。

| 芯片 | 指南版本 | Python |
|---|---|---|
| 昇腾 | 0.6.1+ascend3.5 | 3.11 |
| 沐曦 | 0.6.1+metax3.6 | 3.12 |
| 海光 | 0.6.1+hcu3.6 | 3.10 |
| 天数 | 0.6.1+iluvatar3.6 | 3.12 |
| 燧原 | 0.6.1+enflame3.6 | 3.12 |
| 国际通用 A | 0.6.1 | 3.12 |

- 包索引为 `https://resource.flagos.net/repository/flagos-pypi-hosted/simple`。指南安装步骤会卸载 Triton；只能在目标隔离环境中按需执行，不改当前共享环境。
- TLE-Lite：以较小改动扩展已有内核；TLE-Struct：显式组织计算与数据的结构映射；TLE-Raw：接入厂商原生语言。它们是不同控制层次，不是保证收益的升级顺序。
- 原语支持按芯片不同。指南介绍异步加载、tile 提取/插入、显式管道、GPU 本地缓冲区/搬运/布局/同步、DSA 缓冲区/流水线等能力；不能据名称认定某目标支持。
- 指南提醒：使用 TLE 时，昇腾 DSA 与通用 GPU 需要不同实现，并提到在同一提交文件内包含两类代码。具体实现组织还必须满足本题静态检查与路由契约；不因此引入被本题禁止的设备分支或 torch 计算回退。
- 手写、智能体和 KernelGen 都是指南列举的开发选项；指南并未要求使用 KernelGen。

## 2. 不得由指南推断的内容

1. 阅读到的安装清单及支持表未列昆仑芯或国际 B；它们的版本与 TLE 支持均为 **unknown**，不是 unsupported。
2. 本机复制的表格勾选符号丢失，不能从空白或问号还原逐芯片支持矩阵。采用任何原语前必须核验原页面或对应版本的官方支持说明、示例与编译结果。
3. 单独下载检查的 FlagTree `0.7.0+xpu3.6` 不等于赛事版本；该构建的 `TLE_SUPPORTED_PRIMITIVES = []` 只说明这个构建的注册表为空。
4. 该构建在 `pm.run(mod, 'make_ttxir')` 异常时统一包装为 `OutOfResources(0, 0, 'uni_sram ...')`。因此本题报错的 Required=0 / Hardware limit=0 不证明实际 SRAM 耗尽。
5. TLE 原语存在、CPU 语义通过、访存指令数下降都不证明目标编译通过或性能提高。

## 3. 固化后的每轮检查清单

### A. 环境与能力先行

- 记录 target、编译器包版本/构建、Python、运行时、硬件和来源；平台未公开的字段写 unknown，不以 wheel 名称补造。
- 分别记录普通 Triton 与拟用 TLE 原语的能力：已验证 / 未知 / 已验证不支持，并附对应版本来源。
- 先找匹配版本与目标的官方最小示例，验证 import、JIT 编译和执行；其他芯片的成功不能替代本目标验证。
- 无目标执行环境时，官方评测可以提供编译证据，但不得声称已在本地复现。

### B. 先兼容，再性能

- 编译失败：保存失败用例、完整 pass 名、定位行与已知版本；优先缩小为最小复现，而非把资源包装标签当根因。
- 编译兼容性假设和性能假设分别记录。一次改变一个可识别的结构，并写出什么结果会否定假设。
- 兼容性通过后再依据实际瓶颈选择：普通 Triton → 必要时 Lite → 证据充分时 Struct/Raw。不要为了使用 TLE 而增加管道、搬运或同步。
- TLE 版本与本题契约无法确认时，不提交未经支持核验的 TLE 实现；可继续明确标为实验的普通 Triton 候选。

### C. 验证与提交

- CPU 检查数值、净化规则、base-e/base-2、返回 LSE、stride/mask、覆盖与输入不变性，并带针对新分支的有效负控。
- 冻结源码与环境证据，逐目标计算源哈希；非目标芯片保留已通过字节。
- 打包前检查支持证据、声明成员与路由。指南的多架构实现建议不覆盖本题安全检查。
- 官方结果只绑定上传 ZIP 中的哈希；Failed 单元格点击查看详情，评测中不误报终态、不重复上传。

## 4. Task112 的具体落实

**当前目标首先是昆仑芯编译通过，不是立即追求分数。** 六颗已通过芯片保留 generic 的原始字节。

| 指南中的能力方向 | Task112 对应问题 | 当前决策 |
|---|---|---|
| tile / 布局与映射 | N、B×H、D 的归约和并行映射 | 先核验昆仑芯能力与示例；普通 Triton 的块归约可作为独立实验，不声称属于 TLE 优化 |
| 异步搬运 / pipe | 多 shard 输出加载能否与计算重叠 | 尚无瓶颈与支持证据，暂不采用 |
| 本地缓冲区 / 显式布局 | 数据复用是否值得额外搬运与同步 | 待目标编译通过及实测分析后考虑 |
| DSA 流水线 | 昇腾专用调度 | 昇腾当前已通过，暂不改变其源字节 |
| 分布式原语 / WGMMA | 多设备通信或矩阵乘 | 本题输入已是接收后的张量、计算是加权归约；无对应需要，不因名字相似而采用 |

已观察到：23:04 的 block-LSE 版本和 23:31 的普通 `range(N)` 版本均在 `TritonXPUUnrollControl` 阶段失败。后者否定了“仅换掉 static_range 就能修复”的候选，不证明循环完全无关。

下一步顺序：

1. 从指南原页面的官方文档 / Wiki 链接及赛事可见环境信息核实昆仑芯版本、支持清单和示例；不能用 0.7.0 的扫描代替。
2. 对照可通过的昆仑芯示例，缩小当前失败结构（循环、size-1 广播、归约、非有限值处理等只是待验证因素）。每个实验保留独立假设和失败详情。
3. 如不能取得匹配环境，记录缺口；使用受控的最小普通 Triton 结构实验，不盲加未验证的 TLE 原语。
4. 编译与正确性通过后，才用目标性能证据决定 tile、调度与流水线优化。

本清单是人工执行流程，不宣称 CLI 已自动校验 TLE 能力。现有完整发布证据缺口仍保留，不能由这篇指南补成通过。
