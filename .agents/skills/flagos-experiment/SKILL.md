# 算子实验

读取 [执行手册](../../../competition/WORKFLOW.md) 的实验部分，并读取所选题目的 profile 和 adapter。数学契约来自本题，不能借用其他题目的验证器或成绩。

- 直接编写 Triton 候选；不需要 KernelGen。先提出一个可证伪的假设，再用 `new` 冻结源代码和执行工具。每轮阅读真实结果后决定下一轮，不运行后台优化循环。
- 默认 `bench` 是 30 秒预算的 quick 初筛，最多三个代表性用例。改动只影响部分形状时用 `--cases`；不在每轮重复完整矩阵或启动 profiler。
- 小幅收益或大波动用显式 `--mode confirm` 确认；稳定候选用 `test` 做完整回归。quick 通过不能描述为全用例通过。
- `doctor` 确认所选 GPU 能力。实现的硬件要求可由 `new --requirements` 明确声明，数据类型仍遵守题目契约；不隐式降级 BF16。源码冻结后不能编辑，修改必须建立有父实验的新 run。
- `profile` 只分析明确指定的一个用例；报告区分 CUDA 时间线、launch 资源指标和硬件计数器。权限失败保留为失败，不声称已采集。
- 阅读报告中的初始化、编译、bench 和传输耗时，优化迭代效率时先定位实际慢阶段。
- 连接配置、实验快照及原始 profiler 产物保存在忽略目录。项目日志记录假设、结论、证据 ID 和限制，不记录凭据或服务器地址。
- GPU 实验结果属于非目标证据；进入比赛适配需独立快照和官方目标矩阵。
